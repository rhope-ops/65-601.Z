# Security policy

## Report a vulnerability

Do not write the details of a security problem in a public issue. Use private reporting on GitHub.

1. On GitHub, open the main page of this repository. You see the row of tabs. Go on.
2. Click the tab **Security**. You see the page **Security overview**. Go on.
3. If you see the button **Report a vulnerability**, click it. You see the form **Report a vulnerability**. Go on.
4. In the form, type a title. Describe the problem, the files it touches and the steps that show it. You see your text in the form. Go on.
5. Click **Submit report**. You see your report in the list. The task is complete.

If the page **Security overview** has no button **Report a vulnerability**, private reporting is off. Do these steps instead:

1. On GitHub, on the main page of this repository, click the tab **Issues**. You see the list of issues. Go on.
2. Click **New issue**. You see the form for a new issue. Go on.
3. In the box **Title**, type `Security contact request`. Write no detail of the problem in the issue. You see the title in the box. Go on.
4. Click **Create**. You see your new issue. Wait until the Maintainer answers in the issue with a private way to send the details. The task is complete.

Write no secret, token or personal data in a report or an issue.

## What happens next

The Maintainer reads each report and answers in the report. The Maintainer tells you if the problem is real and which version has the fix. The Maintainer does not publish the report until a fix is available.

## Scope

This policy covers the scripts, hooks and workflows in this repository.
